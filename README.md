# OpenStore repository

This repository hosts the OpenStore catalog and OPK packages separately from
the OpenOS firmware source.

## Publish

Run from the repository root:

```text
python tools/build_opk.py
python -m unittest discover -s test -p "test_*.py" -v
```

Commit and push these generated paths to `main`:

- `store/catalog.json`
- `store/packages/*.opk`
- `update/info.json`
- `update/firmware-<versionCode>.bin`

The configured device catalog URL is:

```text
https://raw.githubusercontent.com/openplace1/OpenStore/main/store/catalog.json
```

Package URLs are generated with the base URL defined in `store/build.json`.

Packages declare minimum OSA SDK and OpenOS version codes. OpenStore disables
incompatible installs, while **Update All** installs every compatible update
after one confirmation.

## Publish a firmware OTA release

OpenOS reads [`update/info.json`](update/info.json). Edit its human release
metadata, build OpenOS, copy the resulting binary under a new immutable name,
then let the release tool fill `size`, `sha256` and `signature`:

```text
# In the OpenOS repository:
pio run

# Back in the OpenStore repository:
python -m pip install -r requirements-dev.txt
cp ../OpenOS/.pio/build/denky32/firmware.bin update/firmware-2.bin
python tools/build_update.py --key /secure/outside-git/openos-release-private.pem
python tools/build_update.py --verify
python tools/build_opk.py
python -m unittest discover -s test -p "test_*.py" -v
```

`build_update.py` requires the Python `cryptography` package. It refuses a
private key stored inside this repository and checks the ESP32 application
descriptor plus the embedded OpenOS target/version marker before signing.
Keep the unencrypted release PEM outside Git with an OS ACL readable only by
the release operator (and the system account used for backups/builds).

This ECDSA trust applies to firmware OTA only. The current OPK catalog still
uses an unhashed/unsigned catalog over no-CA HTTPS; its per-package SHA-256 does
not protect privileged system apps from an active network attacker. Do not
confuse the signed firmware feed with signed Settings/OpenStore packages.

The operator normally changes `name`, `version`, monotonically increasing
`versionCode`, `releaseType`, `description`, `publishedAt` and the versioned
`firmware` filename. `channel` is `stable`, `beta` or `dev`; the official feed
accepts only `stable`. `releaseType` is `major`, `minor`, `patch` or `security`.
`minUpdaterVersionCode` is the minimum OTA protocol implementation, not the
OpenOS release number. Do not edit any field after signing.

Publish the uniquely named firmware and signed manifest in one commit. On a
non-atomic host, upload the firmware first and `info.json` last. Never overwrite
an old firmware filename: a device may have cached an older signed manifest.

### `info.json` fields

| Field | Meaning |
|---|---|
| `schema` | Manifest schema, currently `1` |
| `product` | Fixed `openos` |
| `channel` | `stable`, `beta` or `dev` |
| `target` | Fixed `denky32-wroom32` hardware identity |
| `partitionScheme` | Fixed `openos-dual-v1` |
| `name` | Human release name, maximum 80 UTF-8 bytes |
| `version` | Display version, maximum 24 UTF-8 bytes |
| `versionCode` | Monotonically increasing update order |
| `minUpdaterVersionCode` | Minimum OTA protocol implementation |
| `releaseType` | `major`, `minor`, `patch` or `security` |
| `description` | Release notes, maximum 1,200 UTF-8 bytes |
| `publishedAt` | Publication label/date, maximum 40 UTF-8 bytes |
| `firmware` | Safe relative POSIX path inside `update/` |
| `size` | Generated byte size; maximum 2,031,616 |
| `sha256` | Generated lowercase SHA-256 of the complete binary |
| `keyId` | Fixed identifier of the public key compiled into OpenOS |
| `signature` | Generated base64 DER ECDSA P-256 signature |

The complete JSON document must be at most 4 KB and uses UTF-8/LF. Changing the
public PEM alone does not rotate trust: a future OpenOS build must first embed
the new public key and be delivered with the currently trusted key.
